# FrisianShorts
Fetches a Frisian draughts puzzle from [lidraughts](https://lidraughts.org/training/frisian/), animates the opponent's last move and the solution, and saves it as a 1080x1920 short video with move sounds.

Puzzles come from lidraughts' JSON endpoint, the board is drawn with Pillow, and the video is encoded with the ffmpeg binary bundled in `imageio-ffmpeg`.

## Usage
Requires [uv](https://docs.astral.sh/uv/).
```bash
uv run frisian-shorts        # random puzzle
uv run frisian-shorts 791    # specific puzzle id
```
Writes `puzzle_<id>.mp4` to the current directory.

Title, timings (countdown length, pause between jumps of a multi-capture), sound volume, layout and board colors are constants at the top of `src/frisian_shorts/__init__.py`.

## Assets
`background.png`, `logo.png` and `avatar.png` (1024x1024 channel picture) in `src/frisian_shorts/assets/` are generated by `uv run python -m frisian_shorts.make_assets` (edit it to change the logo text or colors), or replace them with your own files. `move.ogg` and `capture.ogg` are light wood impacts (000 and 004) from [Kenney's Impact Sounds](https://kenney.nl/assets/impact-sounds) (CC0); swap in any other sound with the same names. Fonts: the title is [Nunito](https://github.com/googlefonts/nunito) Black (a static instance of the variable font), the rest is [Poppins](https://github.com/itfoundry/Poppins); both under the SIL Open Font License (`assets/OFL-*.txt`).

## Daily YouTube upload (GitHub Actions)
`.github/workflows/daily.yml` renders a puzzle every day at 06:23 UTC and uploads it to YouTube scheduled to go public at 18:00 Dutch time (`PUBLISH_AT`). Until then it's private, so you can review, reschedule or delete it in YouTube Studio.

`uploaded.txt` is the record of what's been uploaded: `--upload` picks the lowest puzzle id not listed there, and after uploading appends the id, which the workflow commits back to the repo. Add ids to skip puzzles, remove one to allow uploading it again. Running `--upload` with an id that's already listed refuses.

One-time setup:
1. In the [Google Cloud console](https://console.cloud.google.com/), create a project and enable the **YouTube Data API v3**.
2. Configure the OAuth consent screen (External) and set its publishing status to **In production**. In "Testing" the refresh token expires after 7 days and the daily upload starts failing. Google warns that the app is unverified when you sign in; that's expected for a personal app.
3. Create an OAuth client ID of type **Web application** with `https://developers.google.com/oauthplayground` as an authorized redirect URI.
4. In the [OAuth 2.0 Playground](https://developers.google.com/oauthplayground), open the settings (gear icon), tick "Use your own OAuth credentials" and enter the client ID and secret. Authorize the scope `https://www.googleapis.com/auth/youtube.upload` with the Google account that owns the channel (pick the channel if it's a brand account), then click "Exchange authorization code for tokens" and copy the refresh token.
5. Store the three values as repository secrets; `gh` prompts for each value without echoing it:
   ```bash
   gh secret set YOUTUBE_CLIENT_ID
   gh secret set YOUTUBE_CLIENT_SECRET
   gh secret set YOUTUBE_REFRESH_TOKEN
   ```
6. Test it with `gh workflow run daily.yml` and follow it with `gh run watch`.

To upload from your own machine: `uv run frisian-shorts 791 --upload` with the same three environment variables set, then commit `uploaded.txt`.
